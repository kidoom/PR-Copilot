端到端数据流

从用户输入 PR URL 到结构化审查报告的完整旅程

1

🔍 PR 分析

用户输入 PR URL → POST /api/pr/context → 解析 URL → 并行调用 GitHub API（元数据 + 文件 + 提交）→ 解析 Unified Diff 为 Hunk 结构 → 持久化 PRContext

App.tsx routes/pr.ts github/pr.ts
2

📊 静态审查

文件分类（source/test/config/ci/doc）→ 优先级评分（0-100，含风险模式加权）→ 证据规则扫描（密钥泄露、SQL 注入、eval 等 10+ 规则）→ 上下文任务规划 → Token 感知打包为 4 个 Agent Scope

intake.ts priority.ts evidence.ts package.ts
3

🚀 审查启动

用户点击"启动 AI 审查" → POST /api/review/runs → 创建 ReviewRun 记录 → queueMicrotask 异步触发 runReview() → 立即返回 run_id → 前端订阅 SSE

ReviewPanel.tsx routes/review.ts agent/run.ts
4

🤖 Agent 编排

构建 OMA 团队（1 Coordinator + 4 专业 Agent）→ Coordinator 分解目标为子任务 → 并行分发给 security / test / config / quality Agent → Agent 使用受限工具审查代码 → 压缩管线管理上下文窗口

team.ts agents.ts prompts.ts
5

📡 实时流推送

OMA 事件 → event-mapper 转换 → reviewState.pushEvent() → 内存队列 + JSON 存储 + SSE 订阅者 → 前端 TerminalStream 实时渲染：阶段指示器、Agent 卡片、工具调用日志、进度条

event-mapper.ts TerminalStream.tsx ws/events.ts
6

✅ 综合输出

Coordinator 综合子 Agent 输出 → JSON 结构化发现 → extractFindings() 解析 → run.completed 事件 → 前端 FindingCard 渲染（严重性分级、置信度、证据列表、修复建议）→ 持久化到 JSON 存储

agent/run.ts FindingCard.tsx store/session.ts

API 接口

REST + SSE 双协议，支持断线重连与事件回放

方法路径说明
POST/api/pr/context提交 PR URL，获取 PR 上下文（元数据 + Diff + 提交）
GET/api/pr/context/:id获取已存储的 PR 上下文
GET/api/pr/context/:id/files/:file/patch获取指定文件的解析 Hunk 数据
POST/api/review/intake文件分类、语言分布、风险信号分析
POST/api/review/runs创建审查运行，立即返回 run_id
GET/api/review/runs/:id查询审查运行状态
SSE/api/review/runs/:id/events实时事件流，支持 ?after_sequence=N 回放
POST/api/review/runs/:id/cancel取消正在运行的审查
GET/api/pr/context/:id/runs列出某 PR 的所有审查运行
GET/api/pr/sessions列出所有 PR 会话及最新运行
GET/api/health健康检查

关键设计模式

保障安全、可控、可观测的核心架构决策

🔒

工具级作用域强制

Agent 无法超越分配的文件范围。每次工具调用都通过 isPathAllowedByScope() 检查 allowedFiles 和 searchPathScopes，而非仅依赖 Prompt 约束。

💰

Token 预算系统

每个 Agent 有独立的文件读取次数、搜索次数和 Token 消耗上限。budget.ts 跟踪所有消耗，防止工具滥用导致成本失控。

📡

SSE + 轮询降级

SSE 为主通道，支持 Last-Event-ID 断线重连和 after_sequence 事件回放。SSE 断开时自动降级为 3 秒轮询，保证数据不丢失。

🗜

四层上下文压缩

Repair → Micro-Compact → Auto-Compact(LLM 摘要) → Recent Select。128K 窗口管理，确保长对话中 Agent 上下文不溢出。

🧪

Mock 适配器

PR_COPILOT_MOCK_LLM=true 启用确定性测试模式，无需真实 LLM 调用即可验证全流程。返回预设 JSON 发现数据。

🇨🇳

中文输出强制

所有 Agent 输出（发现描述、修复建议）强制使用简体中文。通过 Coordinator Prompt 和 Synthesis Prompt 双重约束。

🛡

路径安全防护

resolveSafePath() 防止路径穿越，isSensitiveFile() 拦截密钥/私钥文件，isIgnoredDirectory() 跳过 .git / node_modules。

📊

事件溯源

所有审查事件以 JSONL 追加写入持久化存储。支持按 sequence 回放、浏览器重连恢复、历史审查重现。

环境变量

核心配置项一览

PORT
后端端口，默认 8000
OPENAI_API_KEY
LLM API 密钥
OPENAI_BASE_URL
OpenAI 兼容 API 端点
OPENAI_MODEL
模型名称，默认 gpt-4o
GITHUB_TOKEN
GitHub Token 回退认证
GITHUB_APP_ID
GitHub App ID
GITHUB_APP_PRIVATE_KEY
GitHub App 私钥
PR_COPILOT_STORAGE_DIR
JSON 存储根目录，默认 ~/.pr-copilot
PR_COPILOT_MOCK_LLM
启用 Mock LLM 适配器（测试用）
PR_COPILOT_REVIEW_MAX_CONCURRENCY
审查任务并发数，默认 1
