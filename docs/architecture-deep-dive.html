03 Agent 团队设计

1 Coordinator + 4 专业 Agent 的完整 Prompt 设计、检查清单与输出格式

🧠 Coordinator Prompt 设计

任务分解指令

将审查目标分解为聚焦的、可并行的子任务。根据 PR 变更内容决定分配给哪些 Agent。

任务指令规范

每个任务必须包含：来自 agentScopes 的具体文件、要查找的具体模式/行为、使用的工具（read_file_patch / search_diff / read_repo_file / search_tests_for）、重试控制（maxRetries: 2, retryDelayMs: 10000, retryBackoff: 2）

最终综合

以 ```json 代码围栏结束，输出 JSON 数组。字段：file, line, severity, category, title, description, evidence, suggestion。合并子 Agent 发现。无问题则输出 []。

中文强制

所有文本必须使用简体中文。通过 Coordinator Prompt 和 Synthesis Prompt 双重约束。

// 核心判断逻辑
isPathAllowedByScope(path, scope):
  if scope == null → true
  if allowedFiles 为空 AND searchPathScopes 为空 → true

🔍 extractFindings() 三级提取策略

Coordinator 输出优先

获取 result.agentResults.get('coordinator')?.output，运行 parseFindingsFromText()。先提取 ```json...``` 围栏块，再尝试匹配顶层 [...] JSON 数组。

子 Agent 聚合

遍历所有非 coordinator 的 agent 结果，各自解析。按 ${file}:${line ?? 0}:${title} 去重（Set<string>）。

Markdown 回退

拼接所有输出，运行 parseFindingsFromMarkdown()。按 ### 标题或 --- 分割，用正则提取 **File:**, **Title:**, **Severity:** 等字段。同样去重。

✅ coerceFinding() 验证逻辑

  • value.file 必须为 string → 否则返回 null
  • value.title 和 value.description 必须为 string → 否则返回 null
  • value.severity 通过 normalizeSeverity() 校验，不在枚举中则默认 'info'
  • value.category 通过 normalizeCategory() 校验，不在枚举中则默认 'code-quality'
  • value.evidence 中每个 item 的 line 非 number 则设为 undefined
